# Reproducibility and results provenance

## Primary source and packaging

- **Source of code:** user-supplied `brain-to-text-baseline-preprocessing (1).ipynb`.
- The repository notebook has **source code preserved**, with its large stored cell outputs cleared for GitHub readability and download size.
- `src/train.py` concatenates the notebook's executable code cells in order. It is an alternative entry point with **the same fixed paths and training implementation**.
- The CSV results were **extracted from the saved notebook execution logs**, and the PNG figures were copied from the notebook's actual rendered outputs. None of these artifacts were synthesized or recomputed.
- The repo was packaged without the Kaggle HDF5 datasets or weights.

## Data requirements

Expected input HDF5 paths are discovered recursively under the configured `data_dir` root, and files are named `data_train.hdf5`, `data_val.hdf5`, and optionally `data_test.hdf5`. HDF5 trials are expected to expose:

- `input_features` dataset with a time × 512 floating-point array;
- trial attribute `n_time_steps`;
- training/validation attribute `sentence_label`.

Input features are **already extracted**, so users should not claim raw-electrode preprocessing or spike sorting as a contribution here.

## Important implementation considerations

1. The data loader uses an internal recursive ordering of HDF5 files/trials; the test `id` is generated by sequential counting, **not extracted from an authoritative competition submission ID**.
2. WER/CER use lowercased strings, without explicit competition-specific punctuation normalization.
3. The code uses `zero_infinity=True`; a separate check validates basic CTC alignment feasibility, but a future code audit could strengthen reproducibility and edge-case testing.
4. Padded sequence smoothing is performed on zero-padded batches. Alternative boundary masking/smoothing choices might change the trained model.
5. The notebook builds the vocabulary only from training transcripts. Unknown validation characters are mapped to the blank ID in the Dataset code for target construction, but validation text metrics use original references; users should verify vocabulary coverage when adapting the dataset.
6. Training can take substantial GPU time; the provided package was **not rerun** to verify bitwise-identical results on different hardware or PyTorch versions.
